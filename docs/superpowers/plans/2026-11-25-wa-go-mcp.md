# `wa-go-mcp` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add built-in MCP support to Wisp (`wisp.exe` + `cmd/wisp-mcp`) with an independent on/off toggle in Wisp Settings so AI assistants can search chats/contacts, read message history, and send text/media after explicit user confirmation.

**Architecture:** `wisp.exe` runs a local authenticated HTTP JSON-RPC bridge (`internal/mcp`) whenever `KeyMCPEnabled` is `"true"`, writing its ephemeral port and bearer token to `%LOCALAPPDATA%\Wisp\mcp.json`. A lightweight `stdio` MCP binary (`cmd/wisp-mcp`) speaks MCP JSON-RPC 2.0 over stdin/stdout and forwards `tools/call` requests to the running Wisp bridge. Wisp's App lock PIN does not disable or block the MCP bridge.

**Tech Stack:** Go 1.26, standard library (`encoding/json`, `net/http`, `bufio`, `os`), `wa-go/internal/store`, `wa-go/internal/whatsapp`, `wa-go/internal/ui` (`lxn/walk`).

**Spec:** [2026-11-25-wa-go-mcp-design.md](file:///d:/project/wa-go/docs/superpowers/specs/2026-11-25-wa-go-mcp-design.md)

## Global Constraints

- Built into Wisp (`wisp.exe` + `cmd/wisp-mcp`); no standalone WhatsApp Linked Device mode.
- MCP on/off toggle (`mcp.enabled`) in Wisp Settings is completely separate from Wisp's App lock (`lock.pin`); locking Wisp's UI must not turn off or block MCP.
- No destructive or admin actions via MCP (no deleting messages/chats, changing settings, or logging out).
- Never send silently without confirmation; sending must use a two-step `prepare_send` -> `confirm_send` flow.
- Never guess on ambiguous recipients; if a query matches multiple contacts/groups, return the candidate list.

## Review Focus

- **App lock active while MCP is enabled:** Locking Wisp's UI (`appLock(true)`) must leave the MCP bridge running and answering tool calls normally.
- **Ambiguous recipient name (e.g. `"Joe"` matching 2+ contacts/groups):** `prepare_send` must return `status: "ambiguous"` with candidates and must not create a `confirm_token` or send.
- **Expired, unknown, or reused `confirm_token`:** `confirm_send` must reject it with a clear error and never send twice on replay.
- **Wisp closed or MCP toggle off:** `wisp-mcp` must return an MCP tool result with `isError: true` and an actionable message instead of crashing or hanging.
- **Missing or directory `media_path`:** `prepare_send` must validate the local file path before issuing a `confirm_token`.

- [ ] **Step 3: Implement `internal/mcp/service.go`**

Implement `Service` with:
- `ToolDef` (`Name`, `Description`, `InputSchema`) and `ToolResult` (`Content []TextContent`, `IsError bool`).
- `list_accounts`: returns `wa.Accounts()`.
- `search_chats_and_contacts`: searches `ListChats` and `People` for the specified account (or all accounts from `wa.Accounts()`), deduplicating by `(account, jid)` and preferring chat/contact names.
- `get_chat_history`: fetches pages from `GetChatMessages` up to `limit` (default 20, max 100). If `account` is omitted and `wa.Accounts()` has 1 account, uses it; if multiple accounts, requires `account` or resolves unambiguously.
- `prepare_send`: validates `text` or `media_path` (using `os.Stat` to ensure regular file), resolves `recipient` (exact JID match, else case-insensitive match on name/phone/JID), returns `ambiguous` if >1 match, or stores a `pendingSend` with a random hex `confirm_token` and 5-minute TTL.
- `confirm_send`: pops `confirm_token` under mutex, checks expiry, calls `wa.SendMedia` (if `media_path != ""`) and/or `wa.SendText` (if `text != ""` and `media_path == ""`), and returns the sent message metadata.
